# Streaming Shuffle — Architectural Decision Log

This log records **every non-trivial design decision** made for the streaming
shuffle feature, as required by the project's **Explainability** rule. Each row
names the decision, the alternatives that were considered, the rationale for the
choice, and the residual risk together with its mitigation. Rows&nbsp;1–8 are the
seed decisions carried forward from the Agent Action Plan; rows&nbsp;9 onward are
the expanded record that makes this the canonical, complete decision log for the
feature. A reviewer should be able to understand each trade-off without leaving
the row.

| # | Decision | Alternatives Considered | Rationale | Risk / Mitigation |
|---|----------|-------------------------|-----------|-------------------|
| 1 | Coexist with the sort path by **composition** — the `StreamingShuffleManager` holds an inner `SortShuffleManager` instance. | Subclass `SortShuffleManager`; fork or duplicate the sort path. | Guarantees **zero regression** and a clean fallback without touching any sort internals; the sort path stays the production-stable default. | Delegation overhead — negligible; mitigated by pattern-matching only on the handle type, never on data. |
| 2 | **Reuse** the executor-scoped `BlockTransferService`; ship the v1 transport as a logging-only stub. | Instantiate a new `TransportContext`; write a bespoke socket layer. | Honors "least modification to the network transport layer" and inherits auth / SASL / TLS from the existing service. | v1 does not yet stream over the wire — mitigated by a documented v2 plan and full fallback to the sort path. |
| 3 | Use **JDK 17 `java.util.zip.CRC32C`** for block checksums. | Hadoop `PureJavaCrc32C`; Guava `Hashing.crc32c`. | Zero third-party CRC dependency; the identical primitive already used by the sort-path checksum. | None material — JDK 17 is the enforced build baseline. |
| 4 | **Reuse Guava** `RateLimiter` (rate limiting) and `Cache` (spill store). | A custom token bucket; a custom LRU spill store. | Both are existing Spark Core dependencies; battle-tested and lock-efficient, so no new code to harden. | Guava API stability — pinned at `33.4.8-jre`. |
| 5 | **Dual activation gate** — the backend is active only when `spark.shuffle.manager=streaming` **and** `spark.shuffle.streaming.enabled=true`. | A single `enabled` flag; a single `manager` value. | Reconciles the two configuration surfaces named in the prompt; defense-in-depth opt-in prevents accidental enablement. | Operator confusion — mitigated by explicit documentation in `configuration.md`. |
| 6 | On producer timeout, trigger upstream recompute via the **standard `FetchFailedException`** path. | Add a custom DAG-scheduler notification API. | Avoids any DAG scheduler modification, respecting the preservation boundary. | Relies on existing retry semantics — acceptable; it matches sort-path behavior exactly. |
| 7 | Surface telemetry through the **`MetricsSystem` `Source` SPI**; add **no new UI**. | Add a dedicated Spark Web UI tab or page. | Automatic fan-out to all configured sinks (JMX / Prometheus / CSV / Slf4j); aligns with §7.12. | Lower in-UI discoverability — mitigated by the external Grafana dashboard and the existing Stages tab columns. |
| 8 | Interpret the **Observability rule via Spark-native facilities** — `MetricsSystem`, MDC-tagged logs, and executor heartbeats. | Add an HTTP `/health` endpoint plus an OpenTelemetry tracing stack. | Spark is a distributed data engine, not an HTTP microservice; native facilities are the idiomatic and testable choice. | The rule wording assumes services — this deliberate deviation is logged here, which is the Explainability rule being satisfied. |
| 9 | Fix the pipelined **block size at 2 MB**. | Larger blocks (fewer round-trips); dynamic per-shuffle sizing. | Bounds per-block latency and the retransmission cost on corruption while giving good pipelining granularity. | Overhead on tiny partitions — mitigated by per-partition buffering before framing into blocks. |
| 10 | **Spill at 80% buffer utilization**, configurable in the range **50–95**. | A fixed, non-configurable threshold; spilling only at the point of OOM. | Relieves memory pressure early while the shuffle keeps streaming; tunable per workload. | Premature spilling — mitigated by making the threshold configurable and by LRU-selective eviction. |
| 11 | Use a **5 s producer connection timeout** and a **10 s consumer heartbeat** interval. | Longer or shorter fixed timeouts; adaptive timeouts. | Fast failure detection without false positives; aligns with Spark's network defaults. | Transient network blips could trip fallback/recompute — mitigated by exponential-backoff retry (1 s start, max 5 attempts). |
| 12 | **Token-bucket rate limiting** with an 80% link-capacity factor and a `maxBandwidthMBps / numConcurrentShuffles` refill rate. | No rate limiting at all; per-connection TCP shaping. | Prevents link saturation and fairly divides bandwidth across concurrent shuffles on the same executor. | Under-utilization if the factor is too low — mitigated by a `0` = unlimited default and by configurability. |
| 13 | Size each per-partition buffer as `(executorMemory × bufferPercent) / numPartitions`, with a **2 MB floor**. | A fixed per-buffer byte size; one global shared buffer. | Scales with both executor memory and partition count; the floor guarantees usable buffers even at high partition counts. | Many partitions shrink individual buffers — mitigated by the 2 MB floor plus spill to disk. |
| 14 | **LRU-spill** buffered partitions to `BlockManager` `DISK_ONLY`. | A custom on-disk format; spilling to the external shuffle service. | Reuses the public block-storage API and standard `ShuffleBlockId` addressing; introduces no new on-disk format. | Disk pressure — mitigated by reclaiming buffer memory within 100 ms of consumer acknowledgment. |
| 15 | Preserve decommission migration by **`MigratableResolver` delegation** to the sort path's `IndexShuffleBlockResolver`. | Implement bespoke block migration; skip migration entirely. | Keeps shuffle-block migration working during executor decommissioning with zero new migration code. | Coupling to the sort resolver — acceptable, because the sort path is stable and left unchanged. |
| 16 | Signal backpressure over an **executor-only `ThreadSafeRpcEndpoint`** named `"streaming-shuffle-backpressure"`. | Reuse an existing RPC endpoint; route signaling through the driver. | Thread-safe, executor-scoped flow control on the existing `RpcEnv`, with no driver involvement. | Endpoint lifecycle bugs — mitigated by binding only on executors and gating on `SparkEnv.get != null`. |
| 17 | **Local-mode safety** — gate lazy collaborators on `SparkEnv.get != null`. | Always instantiate collaborators; maintain separate local-vs-prod code paths. | The manager constructs cleanly in local and test mode without a fully initialized `SparkEnv`. | Null-guard omissions — mitigated by centralizing the gate and by unit tests that construct in local mode. |
| 18 | **Immutable configuration** — changes require an executor restart; no dynamic reconfiguration in v1. | Dynamic reconfiguration pushed over RPC. | v1 simplicity and determinism; avoids mid-application churn of buffer sizes and rate limits. | Operational friction — mitigated by clear documentation and a documented v2 roadmap. This deliberate simplification is logged here per the Explainability rule. |
| 19 | **Isolate all streaming logic** in the dedicated `org.apache.spark.shuffle.streaming` package (zero cross-contamination). | Extend the existing shuffle classes in place. | Keeps the sort path pristine; the only existing-code change is the factory alias plus the five config keys. | Some duplication of reader/writer semantics — mitigated by mirroring `BlockStoreShuffleReader` conventions. |
| 20 | **Dispatch on handle type** (`StreamingShuffleHandle` vs. a base handle) to route between the streaming and fallback paths. | Config-flag branching at every call site; runtime type checks on the dependency. | A single, cheap pattern-match cleanly separates the streaming case from every delegated case. | Handle proliferation — mitigated by using a single `BaseShuffleHandle` subtype that carries the whole resource envelope. |
| 21 | Frame every block with a fixed **32-byte big-endian `StreamingBlockEnvelope` header** plus a CRC32C-checksummed payload. | A variable-length / self-describing header; protobuf or Avro framing. | Fixed offsets give O(1) parsing and a deterministic wire layout; big-endian is the network byte-order convention. The header carries `shuffleId`, `mapId`, `reduceId`, `sequenceNumber`, `checksum`, and `payloadLength`. | Header-format rigidity across versions — mitigated by the producer/consumer version-mismatch fallback check. |
| 22 | **Mirror `BlockStoreShuffleReader`** combine and ordering semantics inside `StreamingShuffleReader`. | Implement a bespoke aggregation/ordering path; eagerly materialize then sort. | Honors `dep.aggregator`, `dep.keyOrdering`, and `dep.mapSideCombine` exactly as the sort path does, using lazy iterator composition with no eager materialization. | Behavioral drift from the sort reader — mitigated by mirroring the established conventions and by integration tests that compare against the sort path. |
