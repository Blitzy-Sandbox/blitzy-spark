# `oss-scan-results/severity-map.md` — the severity mapping, as applied

Generated by the controller from the single mapping structure its adapters read,
so this document and the `severity_norm` column of `findings.json` and
`findings.csv` cannot disagree. One row per tool for **all nine**, including any
that produced no finding.

## The numeric rule, which takes precedence over every label

A numeric CVSS score, wherever a tool emits one, is banded:

| Score | `severity_norm` |
|---|---|
| 9.0–10.0 | Critical |
| 7.0–8.9 | High |
| 4.0–6.9 | Medium |
| 0.1–3.9 | Low |
| 0.0 | Info |

A **CVSS vector** with no label and no numeric score yields `Info`, and the vector
is kept verbatim in `severity_native`. No base score is computed from a vector:
that would mean implementing CVSS arithmetic, and a mis-derived score is an
invented value. An **unrecognized label** maps to `Info` and the literal is listed
in that tool's row below, so a reader sees which values appeared unanticipated. A
row whose native severity is **absent** takes that tool's `Info` fallback.

## Notes that belong to the policy rather than to any one row

* **SARIF levels.** Where a tool's artifact is SARIF 2.1.0, `result.level` (or the
  rule's `defaultConfiguration.level`) is the label: `error` → High, `warning` →
  Medium, `note` → Low, `none` → Info. A numeric
  `rules[].properties["security-severity"]` on the resolved rule takes precedence
  over that label and is banded by the table above.
* **`severity_native` is written verbatim**, as the single value the tool reported —
  label, number or vector — and is `null` where the tool reported none.
* **Gitleaks and Joern emit no severity at all**, so every row of theirs carries
  `severity_native: null` and `severity_norm: Info`.
* **Checkov's open-source build emits `severity: null` per row**, which the
  per-tool absent-value fallback covers: `severity_norm: Info`, with the null
  preserved in `severity_native`.
* **Nothing is inferred from a label's spelling** and no score is derived from a
  vector. Where a tool emits several scores the selection rule above picks one and
  this document names it.
